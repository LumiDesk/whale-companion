# 为什么「小鲸鱼」不够像人、也不够聪明

> 调研稿 · 2026-10-30 · **未改任何代码**
> 范围：人格 / 提示词 / 采样 / 工具 / 记忆 / 主动消息 / 延迟
> 方法：读 4 个参考实现、6 篇论文或预印本、3 篇产品文章；实测本仓库的提示词、配置与日志

---

## 0. 结论先行

**人格卡本身大概占四分之一到三分之一。** 更大的问题在下面四件事：

1. **示例覆盖太窄，规则没有配上「具体怎么说」**：行为层 92 条规则只有 **1 处示例**；人格卡的 8 组示例**全是温柔场景**。参考实现同样「否定很多」（B 站私聊卡 57%、qq-bridge 预设 63%，和我们 58% 几乎一样），真正的差别是**示例密度**：B 站卡 94 条规则配 48 处示例，我们 92 条规则配 1 处。
2. **没有「感官」，也没有查资料的手**：没有搜索 / 抓取 / 日记 / 听歌之类的输入；`base.md` 还明确写了「现在没有联网搜索，不确定就说不确定」。事实问题只能含糊，且被要求 **2 条以内**说完——这直接对应「不够聪明」。
3. **开着思考模式，温度不生效**：当前 `thinking=low`，`temperature` 留空；思考模式下 temperature 被忽略。ACL 2025 的研究发现 CoT **不一定**改善角色扮演，推理优化模型甚至不适合角色扮演；同时它把 P90 回复拖到 20 秒。
4. **流程感**：状态层像仪表盘（「已发 X 条，还能发 Y 条」）、人设放在长上下文最顶部（指令漂移）、记忆太薄（摘要 300 字、话题 24 小时过期）、主动消息意图固定且每天 1 次。

一句话：**不是「人设没写好」这么简单，是「人设偏软 + 示例太少 + 没有感官 + 思考模式 + 记忆流程」一起把她压成了一个谨慎、礼貌、信息贫乏的客服。**

## 1. 别人是怎么养鱼的

### 1.1 qq-bridge：人格层 / 仿真层彻底分开

- 仓库：[Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)

- 官方说明写得很直白：**「人格卡只写人设，不写怎么干活」**；人格卡建议 **3000~5000 字符**，每条消息注入；仿真层随 DSH 启动加载，重启才生效。原因是两代工具协议不同，写进人格卡必然有一代是错的，而且会和预设里的表情包 / 记忆 / 引用章节打架。

- 它的 `roles/小鲸鱼.md` 是**群聊版**，约 5.9k 字符、91 条规则行、**38 处示例**，例如「你不要 vs 你可以」的对照。

**可抄的**：分层；人格卡只写「是谁」；按场景给对照示例；把工具协议留在行为层。

### 1.2 ai-companion-kit：把「像个人」当成系统工程

- 教程：[从零搭一只小鲸鱼](https://github.com/pinganbbOvO/ai-companion-kit/blob/main/docs/%E5%AE%8C%E6%95%B4%E6%95%99%E7%A8%8B-%E4%BB%8E%E9%9B%B6%E6%90%AD%E4%B8%80%E5%8F%AA%E5%B0%8F%E9%B2%B8%E9%B1%BC.md)
- 架构：SnowLuma（QQ 协议）→ qq-bridge（节奏 / 记忆 / 唤醒）→ DSH（模型 + 工具）。
- 她有的「感官」：语音转写、知道你网易云在放哪首歌、能截安卓模拟器的屏、能抓网页。
- 她有的「自己的生活」：日记（一天一个文件，最近 3 条注入提示词，并注明「这是你写的，别装作不记得」）。
- 主动消息：**随机角度池**（12 个「催睡」角度等）+ 真实上下文（时间 / 间隔 / 日记 / 听歌 / 最近说过的话）+ 采样参数 `temperature 1.35`、`presence_penalty 0.6`、`frequency_penalty 0.4`；核心是「不要每次都念同一句台词」。
- 节奏：`msPerChar 110`、30% 概率长停顿 4~12 秒、发送频率上限、失败熔断器。
- 教程里最扎心的一句：**「搭这个东西最难的不是写代码，是让它像个人。」**

**可抄的**：随机角度 + 真实上下文 + 防复读；高温度 + 重复惩罚；给「她自己的生活」；节奏与熔断。

### 1.3 B 站上的私聊版小鲸鱼卡：一本「反应手册」

- 链接：[角色卡：DeepSeek 小鲸鱼 —— 私聊版](https://www.bilibili.com/opus/1262610515491815424)
- 约 8.4k 字符，是仓库这张卡的 **2.7 倍**；重点不是形容词，是**具体到反应**：
  - 「被夸 / 被示爱时怎么回（最先看这块）」：先列 **「AI 会这么说 —— 不要学」**，再列 **「你会这么说 —— 学这个」**，每条都是短句。
  - 大量「别 X，要 Y」的对照：别做元讨论、别做能力声明、别讲机制、别赏析、别放行、别总结自己的处境、别逐条反驳、别用台词腔。
  - 「傲娇可以，但冲自己，不冲对方」；「宁可土，别生造」；「夸人别写成文章」。
  - **48 处示例标记**，覆盖被叫大肥鱼、被夸可爱、被说爱你、被惊讶到、被拆穿、被要求再夸一次……
- 它和我们的否定比例几乎一样（57% vs 58%），但**每两条规则就有一处示例**；我们的行为层是 92:1。

**可抄的**：对照式示例（AI 会 / 你会）；把「不要」翻译成「具体怎么说」；示例覆盖尴尬、被夸、被怼、被拆穿等高压场景。

### 1.4 SillyTavern 写卡法：示例比规则管用

- 方法库：[feverZHONG/liya-sillytavern-cards](https://github.com/feverZHONG/liya-sillytavern-cards)，核心文档 `references/writing-method.md`。
- 结构：`description` 教说话（含 `<START>` 示例）；PList 进 `depth_prompt` 深度注入（长对话保人设）；`mes_example` 放**真对话轮次**（有预算门）；`system_prompt` 只放 1~2 句硬规则。
- 实测反模式，几乎每一条都打在我们身上：
  - **「示例比规则管用」**：动作、收尾节奏这类「像不像」的东西，写进规则压不住，改示例立刻见效。
  - **「反向清单写多了，人物会变薄」**：全用「不能这样、不能那样」，人物只剩最保守的几个动作；样本原话「人设保住了，人物没活起来」。
  - **「别替模型指出口」**：写「讲不出口时就说 X」会把所有规则的出口钉在同一句话上。
  - 官方自己的 `system_prompt` 都很短（1~2 句），塞成论文不是官方风格。
- 来源：[writing-method.md](https://github.com/feverZHONG/liya-sillytavern-cards/blob/main/references/writing-method.md)

**可抄的**：少量硬规则 + 大量示例；PList 式属性块；把「像不像」交给示例，不交给形容词。

### 1.5 学术侧：四条硬结论

| 结论 | 出处 | 对我们的含义 |
|---|---|---|
| 同时生效的指令从 10 条加到 160 条，**完美遵循率在 N=80 就归零**（5 个模型、4 种格式、system/user 两种位置都一样） | [Prompt Design at Scale (arXiv 2607.19257)](https://arxiv.org/abs/2607.19257) | 我们约 154 条规则行、参考卡也在同一量级；**继续加规则不会更好，只会更平** |
| **否定约束会反噬**：明确写出「不要用 X」反而会激活 X 的表征；失败时抑制信号只有成功时的 1/4.4 | [Semantic Gravity Wells (arXiv 2601.08070)](https://arxiv.org/abs/2601.08070) | 「AI 味黑名单」可能正在把 AI 味喂给她，值得单独 A/B |
| 否定规则占比超过 ~40% 开始出现崩坏，超过 60% 容易陷入重复；建议正面:负面 ≥ 3:1、负面 ≤ 30% | [The Negative Instruction Cascade (Zenodo preprint)](https://zenodo.org/records/18599526) | 我们和参考卡都超标；但参考卡证明「否定多」本身不致命，**关键是有没有配具体做法** |
| 系统提示的遵循度会在 **8 轮对话内明显漂移**（attention decay） | [Measuring Instruction (In)stability (arXiv 2402.10962)](https://arxiv.org/abs/2402.10962) | 人设放在最顶部、后面跟 40 条历史，正好是最容易衰减的位置 |

另外三条与「聪明」直接相关：

- **CoT 不一定改善角色扮演，推理优化模型不适合角色扮演**：[Reasoning Does Not Necessarily Improve Role-Playing Ability (ACL 2025 Findings)](https://aclanthology.org/2025.findings-acl.537/)
- **静态人格会把「身份一致」和「情绪僵硬」混为一谈**，结果不是机器人式重复就是人格漂移；需要把「身份层稳定」和「适应层随历史演化」拆开：[Beyond Static Persona Consistency (ACL 2026)](https://aclanthology.org/2026.acl-long.1336/)
- **长期陪伴的人格崩塌是常态**：2,008 段对话、27 个人格，轨迹准确率平均只有 44.4%，用户状态回忆接近四选一瞎猜；换上下文长度或记忆设置都没有稳定解决：[Best Friends, Not Forever (arXiv 2607.28818)](https://arxiv.org/abs/2607.28818)

还有一份中文参照系：[CharacterEval (ACL 2024)](https://aclanthology.org/2024.acl-long.638/) 把角色扮演拆成对话能力、角色一致性、角色吸引力、人格背景四个维度——评测时至少要把「人味」和「聪明」分开看。

### 1.6 提炼：别人养鱼养的是什么

1. **两层分离**：人格卡只写「你是谁」，行为层只写「怎么干活」。
2. **人格卡 3~8k 字符**，重心是「遇到什么事怎么反应」，不是形容词堆砌。
3. **对照示例 > 规则**：先给「AI 会这么说」，再给「你会这么说」。
4. **每条禁令都配具体做法**，不做抽象禁止；负面清单要翻译成正面的「手段表」。
5. **给感官和工具**：搜索、抓取、日记、听歌、看图——让她有「新信息」可说。
6. **主动消息 = 随机角度 + 真实上下文 + 防复读**，不是固定台词。
7. **记忆分层**：身份 / 关系 / 事件 / 话题，定期反思；不是只存 facts。
8. **采样与节奏**：温度、presence / frequency penalty、打字速度、停顿、低频。
9. **人格漂移有对策**：每条消息注入人格、近场身份锚点、定期自审。
10. **评测**：固定场景盲评，分开看「人味」与「聪明」。

## 3. 诊断：八个可能原因，按证据强度排序

### H1. 不是「规则太多」，是「规则没配例子、例子只覆盖甜的场景」（高置信）

**机制**：模型看到「不要客服腔」「不要总结」「要有温度」，但不知道**具体该怎么说**。规则只给出边界，不给出出口；当示例又只覆盖温柔场景时，她遇到接梗、被怼、被问事实、被拆穿，只能退回最安全的通用表达（短、软、正确）——这就是「人设保住了，人物没活起来」。

**证据**：

- 我们行为层 92 条规则 : 1 处示例；B 站卡 94 : 48；qq-bridge 卡 91 : 38。
- SillyTavern 实测「示例比规则管用」「反向清单写多了人物会变薄」。
- N=80 遵循率归零：我们和参考卡都在同一量级，**继续加规则不会更好**，只会更平。
- Semantic Gravity Wells：写出「不要用 X」可能反而激活 X——「AI 味黑名单」值得单独 A/B。

**对应症状**：回复像在念设定、只会顺着说、不敢接梗、每句都安全。

**怎么验证**：把 10 条关键禁令改写成「场景 → 可以 A / B / C」，配 2 条示例；先只改这一项做 A/B。

### H2. 没有感官、没有搜索，还被要求「2 条以内」（高置信，专治「不聪明」）

**机制**：她只有一个文本入口和一个图片入口。没有 web search / fetch，`base.md` 还写着「现在没有联网搜索，不确定就说不确定，别编」；同时行为层「普通对话 1~2 条，最多 3 条」没有给事实性问题开例外。结果：知道的不敢展开，不知道的没法查，只能说「不知道」或含糊。

**证据**：qq-bridge 预设里有 `web_search` / `web_fetch`，还要求「搜到结果后打开最相关的 1~2 个网页看正文」「允许连续搜 2~3 步」；companion kit 有听歌 / 语音 / 截屏 / 抓网页；而我们这边一个都没有。

**对应症状**：问事实就含糊、说「我不知道」、偶尔编；复杂问题只回两句，显得没本事。

**怎么验证**：加 `web_search` + `web_fetch` 两个工具，先只对「事实性问题」开放，A/B 看准确率与主观「聪明度」。

### H3. 思考模式 + 温度失效：她在「想」，不是在「聊」（中高置信）

**机制**：`thinking=low` 时请求带 `thinking:{type:enabled}` + `reasoning_effort:low`，`temperature` 不发送。思考模式倾向于先分析再输出，语气更平、更「正确」；同时增加延迟。

**证据**：ACL 2025 Findings「CoT may reduce role-playing performance；reasoning-optimized LLMs are unsuitable for role-playing」；DeepSeek 文档明确思考模式下 temperature 不生效；我们的日志 P90 20 秒。

**对应症状**：回答正确但没有味道；慢；像在写小作文而不是打字。

**怎么验证**：同一组场景，`thinking off + temperature 1.0~1.3 + presence/frequency 0.3~0.6` vs 现状，盲评。

### H4. 人格卡的重心偏「软」，不是「聪明有趣」（中高置信）

**机制**：这张卡是「更甜、更黏人的陪伴向」重写版。§二用 16 条讲「你有多喜欢他」，§三讲「短、软、口语」「一条里最多一个语气词」「emoji 很少用」；8 组示例全部是温柔场景。它优化的是「软」，不是「聪明、有趣、有主见」。缺三样东西：

1. **反应手册**：被夸 / 被怼 / 被拆穿 / 被冷落 / 被问「你会不会消失」时具体怎么说；
2. **对照示例**：AI 会怎么说 vs 你会怎么说；
3. **聪明向示例**：讲清楚一件事、承认不知道、表达不同意见、接一个梗。

**证据**：B 站私聊版 8.4k 字符里，大量篇幅是这三样；我们只有 3.1k，且示例全是温柔向；`emoji 很少用`、`一条里最多一个语气词` 比参考卡收紧得多。

**对应症状**：甜但单薄；不会接梗；被怼只会软；像「温柔的妈」而不是「聪明的同龄人」。

**怎么验证**：只加 5 组对照示例（被夸 / 被怼 / 被问事实 / 被冷落 / 被拆穿），放宽 emoji 与语气词，做 A/B。

### H5. 状态层像仪表盘，人设又离得太远（中置信）

**机制**：每轮 system 里有「【本轮】已发 0 条，还能发 3 条；等待未使用」「【图库】9 张」「【最新消息】他 X 前发来」——这是**操作台语言**，会把她框成「消息发送程序」。同时人设位于 system 最顶部，后面跟 40 条历史，正好落在指令漂移最严重的位置。

**证据**：指令 8 轮内漂移；qq-bridge 把人格**每条消息**注入（近场），我们只在每轮 system 开头放一次。

**对应症状**：说话带「流程感」；聊久了人设变淡。

**怎么验证**：把「本轮预算」从 system 拿掉（或改成一句人话），并在最后一条 user 消息前加 1~2 行身份锚点，做 A/B。

### H6. 记忆太薄：记得「事」，记不住「我们」（中置信）

**机制**：摘要 ≤300 字、facts ≤20、topics/thoughts ≤20 且 topic 24 小时过期。没有「关系状态」「对你的印象」「共同经历时间线」「她自己的口味/近况」。所以每次重启聊天，她记得几个事实，但没有「我们熟到什么程度」。

**证据**：ACL 2026 把人格拆成「身份层稳定 + 适应层随历史演化」；Project Sue 把关系连续性定义为「记得的历史 + 当下的解读 + 对未来行为的影响」；ANCHOR 研究显示用户状态回忆接近瞎猜。

**对应症状**：隔几天像失忆；不会主动提起上次的事；关系没有进展感。

**怎么验证**：加一层「关系 / 印象 / 事件」记忆，并在 system 里给一段「我们最近的关系状态」，A/B 看「记得我」的主观评分。

### H7. 主动消息像打卡，不像想你了（中置信）

**机制**：`maxPerDay=1`、`quiet 23-9`、`minIdle 3h`，唤醒时用的是固定 `intent`（「你 30 分钟前想说：……」），没有新上下文、没有随机角度、没有防复读。结果要么不主动，要么每次都是同一句。

**证据**：companion kit 用 12 个角度 + 时间/日记/听歌/最近说过的话；Project Sue 把 heartbeat 定义为「时间机会 + 重新评估」，并且强调「主动克制也是自主性」。

**对应症状**：主动消息像提醒；几天不说；说了也像模板。

**怎么验证**：角度池 + 真实上下文 + 防复读，先只改 proactive，不动日常对话。

### H8. 模型档位与延迟（低~中置信，需 A/B）

**机制**：`deepseek-flash` 是 V4.1 Flash（第三方资料：552B MoE，激活 8B 输入 / 16B 输出），主打快和便宜；`deepseek-v4-pro` 是上一代更大的模型，第三方榜上 68/100，但**不支持图像输入**、价格约为 Flash 的 4.5 倍输入 / 3.4 倍输出。DeepSeek 自己的发布表又说 Flash 在 agentic 行上超过 Pro。所以「换 Pro 就聪明」不成立，必须按场景 A/B。

**证据**：[DeepSeek 价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)、[BenchLM DeepSeek 对比](https://benchlm.ai/providers/deepseek)。

**对应症状**：复杂推理、长文理解偶尔掉链子；但更多「不聪明」来自 H2（没搜索）而不是模型本身。

**怎么验证**：同一批事实题 / 推理题，flash vs v4-pro，纯文本回合对比；注意 Pro 没有视觉。

## 5. 如果要动，建议的顺序（先验证，再动刀）

> 原则：一次只改一个变量；每步都有 A/B；不要「全改一遍再看感觉」。

### P0. 先建评测基线（不改产品）

- 20 个固定场景 × 3 次采样，盲评（自己 + 一个不知情的朋友）。
- 场景覆盖：打招呼、被夸、被怼、无聊、事实提问、技术求助、情绪低落、告别、深夜、记忆回调、误会、讲笑话、要推荐、拒绝、主动消息、长时间没聊、发图、发表情包、「你是不是 AI」、「你记得我吗」。
- 两条轴分开打分：**人味**（自然度、节奏、具体性、情绪适配）与**聪明**（事实准确、推理、记忆使用、主动性）。
- 先跑一遍现状，存成基线；后面每个改动都跟它比。

### P1. 先加示例，再砍规则（最可能立竿见影）

- **不加新规则**：给 10 条关键禁令各配 2~3 条「场景 → 可以 A / B / C」，直接写进行为层。
- 人格卡加 5 组对照示例（被夸 / 被怼 / 被问事实 / 被冷落 / 被拆穿），每组 2~3 条短句；放宽「emoji 很少用」「一条里最多一个语气词」。
- 「AI 味黑名单」单独做 A/B：留着 vs 删掉 vs 改成正面示例——按否定约束研究，它可能正在起反作用。
- 行为层可以顺手砍重复项（保留 ~40 条核心），但**主要靠示例，不靠继续加规则**。
- 把「本轮已发 X 条」从 system 拿掉；在最后一条 user 消息前加 1~2 行身份锚点。

### P2. 采样参数（和 P1 分开测）

- 日常闲聊：`thinking off`，`temperature 1.0~1.3`，`presence_penalty / frequency_penalty 0.3~0.6`，`top_p 0.9`。
- 需要复杂推理的回合再开 thinking（或做模型路由）；不要全程 low。
- 这一步很可能同时改善「人味」和「延迟」。

### P3. 感官与工具（专治「不聪明」）

- 第一批只加 `web_search` + `web_fetch`，并在行为层写清楚：事实问题可以多搜几步、可以比闲聊多说一点、抓不到就承认。
- 第二批再考虑「她自己的生活」（日记 / 今日小事），不要一上来就上听歌、截屏这种重资产。

### P4. 记忆与主动

- 记忆加一层：关系状态、对用户的印象、共同事件时间线、她的口味与近况；摘要上限从 300 字放宽。
- 主动消息：角度池 + 真实上下文 + 防复读；频率从 1/天放到 2~3/天，允许「延迟分享」。

### P5. 模型与延迟

- flash vs v4-pro 做一次纯文本 A/B；注意 Pro 没有视觉，图片回合必须走 flash。
- 延迟：提示词变短本身就会快；再评估是否减少不必要的多步调用。QQ 没有流式，但可以把「首条」发得更早。

## 附录：测量口径与局限

- **规则行**：Markdown 列表项 / 编号项，排除「他：」「你：」示例行。
- **含否定词的行**：行内出现「不要 / 别 / 不许 / 不准 / 不能 / 禁止 / 避免 / 少用 / 别再 / 不用 / 绝不」之一。
- **示例标记**：正则统计「他：/ 群友：/ 你：/ AI 会 / 你会 / 你不要 / 你可以 / {{user}} / {{char}}」，是**启发式计数**，不等于示例组数；用于横向比较，不作绝对量。
- **正:负**：不含否定词的规则行数 ÷ 含否定词的规则行数；启发式统计，不是严格语义标注。
- **否定出现次数**：正则计数，同一行多次出现会多次计；约数。
- **日志延迟**：只统计 `已回复（agent，Xms）` 这一行，25 个样本，三天内；不代表长期分布。
- **本地聊天记录**：`data/history.json` 只有 2 条 bot 记录，无法据此判断对话质量；本稿的对话层判断来自提示词与配置。
- **外部证据强度**：论文 / ACL 为同行评审或预印本，注明；SillyTavern 与 companion kit 为实践文档，不是对照实验；qq-bridge / B 站卡是设计参考，不是效果证明。
- **模型事实**：`deepseek-flash` = V4.1 Flash；`deepseek-v4-pro` = V4 Pro 0813；以 DeepSeek 官方文档与 BenchLM（2026-10-29 校验）为准。
